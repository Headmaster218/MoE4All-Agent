# Agent 发行剩余工作

## 已确定的方向

MoE4All Agent 是品牌化 DSH 加本项目维护的插件，复用原有 Agent、工具、审批、profile 和市场生态，不新建第二套 Agent 框架。内部包名、CLI 和 `DSH_HOME` 等兼容标识可以保留，但进程必须指向独立的数据目录和端口。引擎内部的资源恢复与管理接口由 Engine 承担，插件负责界面和生命周期接入。

独立 Agent 仓库已经纳入桌面壳、品牌化 DSH、八个插件、干净初始化、固定运行时、Windows 打包 CI 与分层更新入口。已实现机制集中在[当前产品架构](../architecture/product/agent-distribution.md)，不要把这份路线图当成第二份事实文档。

## 仍需交付和验收

1. 完成正式版签名、安装与卸载路径；继续用最终 ZIP 验证长路径解压、移动后重启、升级和回滚。
2. 内置插件随整包更新；可自动检查，但安装必须由用户确认。继续覆盖网络失败、回滚及用户数据保护。
3. 首次引擎连接/可选受控启动，再进入手机连接引导；列网卡、可配置监听地址、鉴权和暴露风险。第三方服务必须主动开启，不能含私人地址、凭据或网络设置。
4. 可选的一键 DSH 迁移采用快照复制，绝不共享可写 profile、session、记忆数据库或设备配对状态；迁移前后两应用仍能独立同时运行。
5. 使用真正干净机器和最终发行包验证插件依赖 materialization、手机端审批/提问、定时任务、模型发现及外部引擎连接。只管理自己启动的引擎，不能停止已有生产服务。
6. 稳定桌面外壳的 DPI、主题、原生文件选择和启动阶段体验，并保持浏览器入口为可选能力。
7. 讨论中的启动恢复能力：由 Engine 提供结构化错误、受策略约束的降级重试与启动阶段控制通道，插件转交用户选择并展示实际配置。目前插件保留原始启动日志与普通重试入口，失败时展示固定的常见调整建议，不分析日志推断原因，也不修改参数后重试；后端自动恢复尚未实施。

生产一致性指使用模式和功能契约，不指复用真实数据。模型发现失败、API 离线、市场不可达和端口冲突也必须可恢复；维护插件独立仓库的内部开发与引擎性能优化保持分线。迁移出处见[DSH 来源与本地改造记录](../evidence/changes/product/dsh-source-and-local-migration.md)。
