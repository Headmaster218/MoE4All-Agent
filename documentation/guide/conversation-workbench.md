# 会话导航与文件工作台

本页记录本轮 Agent 本地源码能力，不代表已经打包、发布或完成整包验收。DSH 仍固定在当前分支，未整体升级上游；手机、EasyRewrite 等维护插件与独立 Engine 均未修改。原 1–24 项的取舍见[功能选择清单](../roadmap/dsh-feature-selection.md)。

## 问题目录

会话页头的搜索按钮打开问题目录，按需读取当前会话全部历史页，只收录用户自己发送的消息，含 steering，不把插件注入、记忆召回或 compaction 的替换副本当成用户提问。目录可以搜索；选择后通过既有历史分页加载目标，并滚动到原始消息，不恢复或调用模型。

本轮不增加历史消息直接编辑，不改变 EasyRewrite 只处理最后一条消息的策略，也不扩展任意旧消息 fork 的能力。目录关闭或导航取消后，不再触发迟到的跳转。失败保留错误与重试入口。

## 本地文件

输入区提供原生文件选择，非图片拖入时按左右两侧选择复制或引用。纯图片拖入继续走已有图片附件机制，手机上传保持原状。

- **复制到工作区**：文件写入当前工作区 `.moe4all-uploads/<唯一目录>/<原文件名>`，不覆盖同名文件；成功后将路径追加到草稿。
- **引用原文件**：验证原路径存在，只追加路径，不复制内容、不扩大模型权限。浏览器不提供拖入文件的原始路径时，需填写完整路径。
- 单文件 UI 上限为 32 MiB；Host 的上传/预览上限通过 `workspaceFileMaxBytes` 配置，默认 32 MiB；目录结果通过 `workspaceFileMaxEntries` 配置，默认 5000 条。大文件可使用路径引用，而不是上传。
- 取消导入或切换工作区后，不会用迟到的返回值改写输入框。切换工作区的引用草稿保留规范 URI，而不是只保留显示标签。

路径是普通用户消息的一部分，不等于把所有格式的文件转换成模型附件。模型读取文件仍经现有工具、权限和审批。

## 文件工作台

页头文件按钮打开工作台；宽窗口复用右侧详情栏，窄窗口切到全宽“文件工作台”标签页。工具结果中的文件路径默认在这里打开，“系统打开”是另外的明确操作。文件标签仅保存路径，不把文件内容写入持久 store。

| 内容 | 当前行为 |
| --- | --- |
| 代码、文本、Markdown、图片 | 内建预览；文本可切源码 |
| 本地 HTML | 隔离预览，支持内联脚本和有限的工作区相对图片、样式、脚本资源 |
| PPTX | 使用固定版本渲染库转换并分页，可展开查看 |
| PDF、旧 PPT、Word、Excel 等 | 暂不提供可靠内建渲染，使用系统打开 |

HTML/PPTX 放在不含 `allow-same-origin` 的 sandbox iframe 中，CSP 禁止网络、子框架、表单及宿主访问；不是可以任意上网或执行 Agent 工具的完整浏览器。HTML 的模块依赖、CSS 内间接资源不保证自动收集。PPTX 不保证复杂动画、SmartArt、字体与 Office 的像素一致性；转换仍在浏览器主线程，ZIP 展开上限 64 MiB、最多 4096 个条目、转换后最多 200 页。文件可读大小上限先于这些限制生效。

只有打开文件或手动刷新才读取内容；切换标签会取消过期读取，失败不会继续显示旧文件。预览 API 仅允许当前会话工作区内的规范路径，拒绝 Git 元数据和已解析的链接越界；外部原路径引用不授权工作台读取该文件。

## 修改记录与 Git

“修改记录”从已加载历史里读取成功结算的真实 tool diff，包含嵌套调用，按日志轮次分组，不根据模型文字猜测文件是否改动。较早记录需先加载对应历史再刷新；不是跨所有历史的独立持久变更数据库，也不自动撤销文件。

“Git graph”读取工作区仓库最多 100 个 commit、当前文件状态和选中文件的 staged/unstaged 总 diff。要求工作区是仓库根目录，命令使用固定参数、literal pathspec，禁用 shell、hooks、external diff 和 textconv。它不包含 stage、commit、revert、worktree 或多 Agent 分支隔离。

上述读取由用户动作触发，不随每个 token 扫描整个目录、Git 或全部历史。

## 自定义 API 思考能力

模型设置可逐模型选择继承、非思考模型或自定义思考档位。档位支持 `off/minimal/low/medium/high/xhigh/max`，保留各档位实际 wire value；`off` 的空值表示不发送该字段。无效声明在保存前拒绝，编辑不会丢失模型的其他隐藏字段。

这只是声明已安装 pi-ai adapter 的既有能力，不会使不支持相应参数的服务自动支持它，也不修改 MoE4All Engine 插件的模型专用设置。

## 验证边界

本轮使用相关包单元测试、现有 slot 组装测试、分 Host/Client 的改动文件语义检查，以及独立组件浏览器检查。实际检查了桌面/手机宽度、暗/亮色、HTML 交互和宿主隔离、真实最小 PPTX 转换。没有完整编译 Agent、重打包、发布、启动推理后端或操作生产 DSH。

客户端目录依赖门禁当前报告 27 项；使用修改前 `61d6e3c` 的内容重放得到同样 27 项，本轮没有新增，不将它报告为整体门禁已通过。组件检查不能代替最终 EXE、真实复杂 Office 文件及生产会话验收。
