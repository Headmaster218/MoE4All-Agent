# 能力中心

能力中心是 Agent 内置的更新入口，不是另一个需要自更新的插件。它直接使用 DSH 设置中的分区，不叠加另一张能力中心弹窗。桌面设置顺序为「模型」「MoE4All」「插件」「能力中心」。语言与四套配色跟随 Agent。普通浏览器访问不提供桌面安装操作。桌面窗口首次采用较大尺寸，之后保存窗口位置、大小及最大化状态；更换显示器后会限制在可见工作区域内，最小化不会覆盖已保存尺寸。

## 更新边界

| 组件 | 发布源与执行器 | 生效方式 |
| --- | --- | --- |
| Agent | `Headmaster218/MoE4All-Agent` Release；复用整包更新器 | 用户确认下载、安装并重启；保留上一版应用 |
| 八个维护插件 | 各自 Headmaster218 仓库的 `release-<package.version>` Release | 用户确认下载并准备，另行确认重启后替换 |
| Engine | 引擎插件现有 Release 管理器 | 独立安装或更新；不自动启动推理，不下载模型 |

自动检查只请求版本元数据，默认开启，并缓存六小时；手动检查可立即刷新。更新下载安装必须由用户确认，检查失败不会触发安装。唯一的首次安装例外是完全未配置的本地 Engine，见下文。预发布默认关闭，不因当前 Agent 是预发布版而自动开启；旧版隐式选择会一次性重置，用户之后的主动选择会保留。预发布开关用于 Agent 和维护插件；维护插件的 `-moe4all.N` 表示发行修订，不单独视作预览版，GitHub 标注的 prerelease 仍受开关限制。Engine 沿用引擎插件自身的发布通道。

只有发现未跳过的新版本时才自动打开设置的能力中心分区；普通启动、已有完成状态、后台检查失败或准备完成不会抢占页面。可对每个组件选择「跳过此版本」，保存在 `data/capabilities/settings.json`；只屏蔽这一版本的自动提醒，下个版本仍会提醒，手动检查与安装不受影响。关闭设置不会取消下载，进度仍可在设置中查看。

Agent 更新不批量升级或降级已有插件，也不捆绑 Engine 更新。整包内的插件组合用于新安装；已有 profile 保留独立安装的版本。Agent 安装前检查所声明的 DSH 宿主版本与已有维护插件的 `engines.dsh`，存在待应用插件变更或不兼容时拒绝停止当前 Agent。未声明宿主版本的整包不能绕过此检查。

## 插件事务

顶部摘要给出当前下一步，组件视图分为「全部」「待处理」「更新记录」。已跳过且没有其他错误的版本不进入待处理，但仍可在全部视图手动安装。检查失败与更新失败分开：前者重试版本检查，后者保留当前运行版本并允许重新准备。Agent 下载失败也可再次明确确认后重试同一目标。更新设置中的通道或自动检查选择变化会刷新元数据，不自动下载安装。

每个组件使用独立卡片展示简介、版本、进度和操作。插件阶段区分下载、校验、准备及重启应用；下载及校验完成后仍运行旧版，卡片会显示「重启并应用」。准备失败时明确提示本次未生效，并提供重试按钮及可展开的错误详情。重启完成且客户端启动确认后，卡片恢复当前版本状态，不永久悬挂「已完成」。每个插件最近一次已确认更新或回退的时间、前后版本保存在更新记录视图，不依赖瞬时成功提示；后台检查不会清除这条记录。待回退状态使用实际恢复版本，不把最新发布版本当成回退目标。

插件资产是可安装 runtime `.tgz`，不是 GitHub 自动生成的源码 ZIP。能力中心固定包名、仓库和下载来源，核对 `SHA256SUMS.txt`、`plugin-release.json`、包名、版本、入口、bundle patch、Node/DSH 与必需宿主 peer 范围；拒绝路径越界、链接、重复文件和安装生命周期脚本。现有 Provider 旧发布允许缺少 release manifest，但仍必须通过 SHA256 与包内容检查。

宿主 peer 版本从实际随包运行时清点，不能仅根据旧插件的依赖列表推导；新版可能新增必需 peer。静态编入浏览器壳的库也需保留真实包及版本，构建时将预装插件必需的宿主依赖纳入部署闭包，不通过假定版本或跳过兼容检查解决缺包问题。

下载后在 `data/capabilities/transactions/` 构造隔离 profile，使用随包固定的 pnpm，禁用安装脚本。其余维护插件固定为当前已安装 runtime 的快照，未知插件仍由原 manifest/lock 约束；不会执行插件源码构建。准备期间不替换运行中的 `node_modules`，不修改用户 patch、会话、记忆、模型或 KV。持久 archive pin 使用相对路径。

快照按普通文件内容保存，不继承 pnpm 的硬链接拓扑，避免打包器等待硬链接导致准备无法结束。CLI 若存在未完成操作却已无活动任务，必须报告非零退出，不能把未完成状态误报为成功。

用户确认重启后，Agent 先关闭自己托管的服务，再以日志记录逐项切换 `node_modules`、manifest、lock 和 workspace 文件。激活后等待桌面客户端桥接完成启动确认；切换中断或未确认启动的事务在下次启动时恢复。此确认不是对所有插件功能的完整验收，也不是 GPU 推理测试。

准备后的 profile 或暂存文件若发生变化，会取消本次切换并保留错误，继续启动未被替换的版本。切换执行失败时，只有确认旧 profile 已完整恢复才继续启动；不能证明恢复完整时停止启动，避免运行混合版本。

能力中心提供取消准备和回退上一次插件更新。回退只涉及插件代码与依赖，不回退插件数据；如果 manifest、lock、workspace 或维护插件版本已被其他工具修改，拒绝覆盖。事务清理保留当前及回退 profile 引用的 archive，不删除用户数据。一次只允许一个待应用插件事务，完成或取消后可继续更新其他插件。

## 引擎与进程

能力中心只连接当前 Agent 的 loopback 引擎管理 API。完全未配置、没有已安装版本且无可用或运行中引擎的本地模式，会自动尝试一次下载并安装最新稳定引擎；不会启动推理或下载模型。失败后不在每次启动循环重试，用户仍可手动安装。已托管引擎可独立更新。正在运行的托管引擎需先在引擎设置中停止，不能直接更新。手动配置、已有版本及 connect 模式的外部引擎不会被首次安装流程接管、停止或替换。

引擎管理插件必须声明支持确认版本绑定，能力中心才开放引擎下载；旧插件需先更新，原有引擎设置入口仍可使用。下载前重新查询的版本若与用户确认的不一致，拒绝下载并要求重新确认。旧 profile 中的自动下载开关在 Agent 启动准备时关闭，不因整包升级绕过确认。

引擎发布缺少平台资产、网络失败等检查错误会显示为检查未成功；不能把缺少完整发行包解释成正常未安装。托管引擎运行时仍展示已知新版本，但安装按钮保持禁用，并指向停止引擎的入口。

重启 Agent 会中断当前对话和它托管的引擎，因此始终再次确认。独立生产 DSH 和外部 infr 不属于能力中心的进程或数据所有权范围。

## 构建与验证

更新工具依赖固定在 `harness/distribution/update-tools/package-lock.json`，随整包提供，不要求用户先装 Node 或 pnpm。桌面协调器依次使用安装根目录、bootstrap、开发 runtime 布局中的 Node，不能只验证开发目录而遗漏压缩整包布局。事务、状态和设置位于 `data/capabilities`，依赖缓存位于 `cache/node`，与模型、用户会话分开。

核心回归使用 `harness/capabilities/center.test.cjs`，测试根目录与工具目录必须显式指定到隔离 staging/tmp。客户端测试覆盖进程消息、设置分区通知、跳过版本、确认下载、进度、重启确认和订阅释放，浏览器检查中英与四套配色。原生 `--window-state-test` 验证窗口尺寸往返、最大化、最小化及屏幕边界，不启动 Agent 服务。发布前仍需从最终 ZIP 验证完整 Agent 启动、插件冷切换、移动目录和整包更新兼容性，不能用单测代替正式包验收。
