# Agent 体验修复与验证

## 范围

本轮处理 Agent 桌面体验、模型配置和不扩大权限的沙箱兼容性调查。只在 Agent 主仓库及其 DSH 子模块提交代码，不推送、不发版；不改 Engine、Mneme、生产 DSH 或现有 Codex 的配置、账户、服务和权限。超过 1 核、512 MiB 或可能影响性能的操作通过 `D:\cpuandram.lock` 串行执行，锁由本任务持有的文件句柄和随机 token 标识，不删除其他任务的锁。

生成物统一位于 `D:\AIinfr\infr\local-work`，任务标识为 `20261027-qa-desktop-model-sandbox-b61d`。源码快照、隔离安装和临时 profile 位于 `staging/agent/<任务标识>`；原始日志、JSON、截图位于 `evidence/agent/<任务标识>`。测试输入均为合成数据，不使用生产对话或真实凭据。

## 沙箱结论

本轮没有替换沙箱后端，也没有修改沙箱实现或扩大文件、网络、用户凭据权限。

受控探测使用真实 `sandbox-windows-acl` runner，比较宿主、`workspace-write` 和 `read-only` 三种模式。每次只创建本任务随机命名的管道及私有工作区。结果记录于 `sandbox-narrow.json`：

| 创建方式 | 宿主 | workspace-write | read-only |
| --- | --- | --- | --- |
| 默认管道安全描述符，客户端读写打开 | 成功 | Win32 5，拒绝访问 | Win32 5，拒绝访问 |
| 显式传入已有 token 默认 ACL，客户端读写打开 | 成功 | 成功 | 成功 |
| 默认管道安全描述符，客户端只读打开 | 成功 | 成功 | 成功 |

因此，token 默认 DACL 中已有相应授权，并不能证明第三方运行时通过默认参数创建的管道也采用了它。受限 token 在这些默认管道上无法完成写访问。显式 ACL 的成功只证明自行控制管道创建 API 的程序可以处理这一路径，不意味着可以直接修复 Node/MSYS 创建的所有管道。

没有发现 Agent 层可直接采用、且已证明安全的通用窄修。Node/MSYS 管道项保留 pending；不注入 DLL、不给共享对象增加宽泛 SID、不静默转宿主执行。Schannel/SSPI、交互认证和凭据桥接也不由这项探测宣称已修复。独立 Codex 后端及真实共存安装仍须单独讨论和在可恢复环境中验证。

## 桌面卡顿对照

通过隔离安装、合成 OpenAI 兼容 API 和真实 `ask_user_question` 工具复现：桌面先完成普通生成及停止生成，在问答框填写答案时卡住；同一 Host 上的有窗口 Edge 可以继续。此时服务 HTTP 仍响应，启动器主线程 CPU 持续增加，采样落在 WebView 原生消息处理路径。这里只定位到宿主集成与运行时的交互，不宣称已经定位 WebView 内部实现的具体缺陷。

| 对照 | 结果与处理 |
| --- | --- |
| 关闭 GPU 加速 | 仍复现，不采用 |
| 分别关闭 UIA 功能或平台无障碍集成 | 仍复现，不采用；测试期间 Evergreen Runtime 自行从 155 更新到 156，这些早期尝试不能视为版本恒定的严格 A/B |
| 关闭 `IsNonClientRegionSupportEnabled` | 全部交互通过，但会损失既有原生拖动语义，不作为产品修复 |
| 只移除正文输入框的全局例外，仍全局声明正文按钮 | 仍复现，不采用 |
| 将普通控件例外整体限制到标题标记内部 | 全部交互通过，作为产品修复；保留独立的 `data-moe4all-no-drag`、dialog 和 popover 例外 |

最终启动器直接从源码编译，不包含诊断计数器，也没有关闭 GPU、UIA、平台无障碍或浏览器沙箱。`final-launcher-artifact.json` 记录基线 commit、未提交 patch 和 EXE SHA256；它是本地 QA 成品，不是新的正式发布。此前 ZIP 的 DSH、Node 和插件 payload 没有替换来源。

最终 `actual-ui-results.json` 的 19 项检查全部通过，浏览器与桌面各自完成模型目录与思考参数、停止生成、连续三轮工具问答、取消无首 token 的响应、放弃问题、浅层目录、真实工具读写、文件链接、四种配色和布局检查；最后主动终止测试 renderer 后，Host 仍可访问，原生故障事件也有记录。界面稳态采样各 1.5 秒，均记录 91 帧，帧间隔 p95 分别约 16.8 ms、16.9 ms，无页面横向溢出。这不是长时间性能 benchmark，也不能推导所有机器上的帧率。

新增 `chrome-regions` 回归使用真实 WebView 检查 CSS 计算值、正文按钮和输入框默认区域、标题控件、显式例外、动态正文及 dialog 答案焦点。它不向全局桌面注入鼠标。旧标题栏版本曾通过物理拖动及点击回归；最终版本尝试复跑时，Windows 未允许测试窗口取得前台，安全检查在注入鼠标前拒绝执行。该次物理拖动重测不记为通过，没有抢占输入线程、修改系统前台策略或关闭其他应用。最终产品的拖动规则仍开启，标题标记和原生窗口命中代码未改动。

## 未覆盖的工作

- 本轮不新增标题专属设置 UI。既有配置可成对指定标题 provider/model，默认沿用主会话的实际模型路由；pi-ai/DeepSeek 对 `session-title` 请求关闭思考。
- 不重做完整的提供商模型能力架构；思考控件仍由确切模型的能力声明决定，而非提供商级全局开关。
- 不改 Mneme 画像、重要性、衰减、Office 支持、Engine 模块化或 ASR。
- 强制结束隔离测试实例时观察到配置写锁残留，随后模型发现和配置保存都会超时。`atomic-write` 当前契约明确不自动抢占遗留锁；不能按文件年龄或单个 PID 猜测性删除真实用户的锁。本轮只在确认测试目录静默、已知写锁 PID 不存在后，恢复自己的测试 fixture，并保留记录。异常终止后的产品级恢复和更完整的优雅退出需另行设计，不宣称已修。
- 模拟 API 验收证明控制链路，不证明真实模型输出质量、吞吐或 GPU 稳定性。桌面卡顿和问答超时只有在相应实际链路完成后才记录复现或未复现结论，不归因于大小核或硬件加速猜测。
